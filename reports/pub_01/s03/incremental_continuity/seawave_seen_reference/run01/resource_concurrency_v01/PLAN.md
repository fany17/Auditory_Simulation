# D27 运行资源修订草案

本修订只增加调度并发。原 D27 V04 的训练脚本、解释器、数据、模型、种子、优化器、调度器、保存点与选点保持原定义。实际接管以本草案、源码、隔离验证和独立审核回执绑定的资源协议为准。

接管仅针对当前调度父进程和报告等待进程。原 initial 1024 与 2026 继续使用原来的进程、设备和检查点。通过进程目录 FD 核对 PID、UID、startticks、命令与父子关系后，仅对旧调度父发送 SIGSTOP。必须实测整个线程组停止，两个原训练子进程仍活动，且原登记和内核子进程集合没有新派发。接管 lease 独占创建。SIGSTOP、SIGCONT、SIGTERM、SIGKILL 的目标均为已验证的进程目录 FD。

先仅放行第三个既定 initial 31415，单卡最多两个登记的正式 worker。GPU 必须没有未登记计算进程，且采样可用显存至少 16 GiB。后续个人任务须等自己的 initial 正式终态与真实退出，仍使用原先独立优化与选点。保留原线程和环境设置，调度器和监护进程使用系统 Python，训练及正式末尾聚合明确使用原 env01 Python。原两 worker 的环境只在内存比对和继承，原始环境内容不写盘。

新训练先由独立监护进程登记，登记落盘后才放行正式解释器。监护进程作为真实父进程保存 wait 返回值，即使新调度器退出仍能写入训练退出回执。已有目录、活动身份和完成任务不能重复启动。新训练写 ATTEMPT_001，原训练只在 ATTEMPT_000 追加真实退出回执。原父在两个原训练退出前保持停止，Linux 保留同 UID 的未回收僵尸。独立回执保存 stat 字段 52 原码、原父和子身份、状态、观察时间、实际训练终态和计时。两条证据落盘后才终止旧调度父进程，旧调度父的退出码保持未知。

原报告等待进程在新训练已放行且新报告等待进程的真实身份已登记后才终止，原启动回执保留。新等待进程绑定新调度器身份、资源协议与既有报告源。它只在完整正式终态、资源终态、150 个真实 worker 退出和旧报告进程退出均核验后出报。新调度器在聚合时 exec 到原 env01，进程身份延续。

提交点为放行意图回执写入。此前普通错误关闭尚未放行的管道并在核验后恢复旧父。若协调器在此阶段被硬终止，人工核对 lease、意图文件缺失、无第三个训练登记或目录、两个原子仍是旧父的子进程后，可以用原 FD 机制恢复旧父。出现放行意图后，即使新调度器失败，旧父都保持暂停，原 worker 继续。旧父保存的僵尸为后续恢复保留真实退出证据。新监护进程保存其真实子进程状态。依据这些回执单独审阅恢复，不能把未知退出码记为零或再次启动已放行案例。若外部干预导致旧父已消失，必须保留可能缺失的原退出证据并停止自动继续。

隔离验证使用自建父子进程和纯逻辑用例。首次尝试因原 Python 缺少 pidfd_open API 在发信号前停止。随后实测服务器内核 pidfd_open 为 ENOSYS，系统 Python 可用同一 /proc 目录 FD 的 pidfd_send_signal。异父观察者读取的退出码与原测试父进程 Popen 等待结果一致。验证不读取信号或权重、不运行模型、不对正式进程发信号。
